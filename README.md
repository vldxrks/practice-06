# Практична робота 6.1

Варіант 1 - лічильник з історією. Flutter SDK, без сторонніх пакетів.

```bash
flutter pub get
flutter run -d chrome
```

## Етап 1 - підняття стану

Спільний стан живе у `_CounterAppState`, над обома сторінками `Navigator`.
Обидва екрани отримують дані та колбеки через конструктори.
Зміни виконуються через `setState`. `Navigator.pages` передає нові значення
також уже відкритому екрану історії.

| Дані | Місце | Чому |
| --- | --- | --- |
| Значення та історія | `_CounterAppState` | Потрібні двом екранам і бейджам |
| Крок 1 / 5 / 10 | `_CounterControlsState`, `setState` | Локальний вибір користувача |
| Відкрита сторінка | `_CounterAppState`, `setState` | Стан навігації |

`CounterEntry` незмінний, має `const`-конструктор. Історія виводиться через
`ListView.builder`, найновіші записи зверху. Від’ємна зміна відхиляється зі
`SnackBar`, не потрапляє до історії. Скидання 0 у 0 не є зміною. Очищення
історії не змінює лічильник. Після перезапуску застосунку дані скидаються.

Контролери вводу не створюються: у цьому варіанті немає текстових полів.

Перевірка: `flutter analyze` та `flutter test`.
